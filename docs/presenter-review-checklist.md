# Presenter review checklist

Use this checklist after the QA artifact is generated and before presenting.

## Before rehearsal

- [ ] Open the Markdown QA report and resolve all `error` findings.
- [ ] Review all `warning` findings and decide whether to fix or consciously accept them.
- [ ] Confirm the generated deck has the expected slide count and story flow.
- [ ] Check that every slide has speaker notes written in presenter language.
- [ ] Confirm all referenced diagrams are present and visually ratio-safe.

## Proof review

- [ ] Proof slides show artifacts that are specific enough to be credible.
- [ ] Guardrails are visible, plain-language, and not buried in speaker notes.
- [ ] Any audit-trail or human-review claim is backed by an artifact or caveat.
- [ ] Proof thumbnails are used as evidence anchors, not as unreadable dashboards.

## Metrics review

- [ ] Metrics have sources, caveats, assumptions, or confidence labels.
- [ ] Directional productivity metrics are not described as guaranteed savings.
- [ ] Operational metrics are not promoted to SLA claims unless the source supports that.
- [ ] The presenter can explain what the number does and does not prove.

## Final pass

- [ ] The opening slide makes the audience care about the context.
- [ ] The proof slide earns trust before the ambition slide asks for belief.
- [ ] The closing line is memorable and action-oriented.
- [ ] The QA Markdown and JSON artifacts are stored with the generated outputs.
