# PresentationKit agent routing

This repo is a small, brand-neutral toolkit for manifest-driven presentation generation. Keep agent work focused on deck intent, manifest data, and renderable surfaces.

## Start here

1. Read `README.md` for the CLI and repository layout.
2. Read `docs/new-agent-start-here.md` before changing deck behavior.
3. Use `docs/contextless-agent-checklist.md` when implementing or reviewing deck features without prior session context.
4. Use `docs/review-checklist.md` before asking for review.
5. Use `docs/brand-pack-workflow.md` when a private brand companion or template should optionally finalize the generated deck.

## Safe edit surfaces

- Deck content and examples: `examples/*.deck.json`.
- Manifest shape and validation: `schemas/deck.schema.json`, `src/validate.js`, and `src/manifest.js`.
- Rendering behavior: `src/deck.js`, `src/diagrams.js`, `src/layout.js`, `src/theme.js`, and related CLI wiring.
- Docs and planning templates: `README.md`, `docs/*.md`, `docs/story-strategy-template.md`, and `docs/metric-defensibility-template.md`.

Avoid adding company-specific names, proprietary screenshots, private metrics, or generated deck output to the repo.

## Generated artifacts

- `dist/` is generated by render/build commands and should not be committed.
- Regenerate diagrams and decks locally when validating render changes.
- Commit source manifests, schemas, code, and docs instead of generated `.svg`, `.png`, or `.pptx` output unless a future task explicitly requests checked-in fixtures.
- PresentationKit builds `.pptx` decks itself. When final delivery needs extra visual QA, template merging, or brand-specific polish, use `docs/companion-pptx-skill-workflow.md` to hand off the generated deck to an authorized PPTX inspection workflow or brand-specific companion skill. Do not replace the PresentationKit build with a companion's custom generator unless a specific PresentationKit limitation is documented.
- When a `brandPack` manifest entry is present, keep the actual template, logo, fonts, icons, photos, palette, footer rules, and private context in the external companion skill. Do not copy them into this repo.

## Verification

Use the smallest command that covers the change:

```powershell
npm run check
npm run render:example
npm run build:example
npm run smoke
```

For docs-only changes, `npm run check` is usually enough to confirm the example manifest still validates. Run `npm run smoke` when render, layout, CLI, schema, or example manifest behavior changes.
